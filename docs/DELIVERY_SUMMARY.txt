4 CORE CHECKS (Run in 10 seconds before solving):

  CHECK 1: Data Structure
  ├─ Are nurse IDs present and unique?
  ├─ Do scenarios have required columns?
  └─ Are all demands non-negative?
  
  CHECK 2: Parameter Ranges
  ├─ Cost hierarchy: c1 < c2 < q_plus?
  ├─ Constraints consistent: n1 ≥ n2, n1 ≥ n3?
  └─ CVaR valid: 0.5 < σ < 0.99?

  ├─ Total capacity ≥ peak demand?
  ├─ Night shift capacity sufficient?

  ├─ Estimates variables, constraints
  ├─ Predicts solve time
  └─ Warns if problem too large

✅ REQUEST #3: PARAMETER SANITY GUARDS
───────────────────────────────────────────────────────────────────────────────
File: validation_framework.py → sanitize_parameters() function

AUTO-FIXES (happens automatically if auto_fix=True):

  1. Cost Hierarchy Violations
     Problem: c2 (150) ≤ c1 (100)
     Fix: c2 = 150.0
     
  2. Constraint Contradictions
     Problem: n2 (10) > n1 (8)
     Fix: n2 = 2 (reset to 30% of n1)
     
  3. Minimum Exceeds Maximum
     Problem: n3 (12) > n1 (10)
     Fix: n3 = 6 (reset to 60% of n1)
     
  4. CVaR Confidence Out of Range
     Problem: σ = 0.02 (too low)
     Fix: σ = 0.95 (standard confidence)
     
  5. Negative Shortage Limit
     Problem: μ = -50
     Fix: μ = 50.0
     
  6. Invalid Solver Time Limit
     Problem: time_limit = -300
     Fix: time_limit = 300
     
  7. MIP Gap Out of Bounds
     Problem: mip_gap = 5.0
     Fix: mip_gap = 0.01

AUDIT TRAIL:
  fixed_params, changes = sanitize_parameters(params, nurses_list, scenarios_df)
  
  for change in changes:
      print(change)
      # Output: "Fixed cost hierarchy: Set c2 = 150.0 (was 100.0)"
      #         "Fixed n2: Set to 2 (was 10, exceeds n1)"

WHAT'S NOT AUTO-FIXED (need human judgment):
  ❌ Demand > Capacity (need more nurses)
  ❌ Missing data (wrong file path)
  ❌ Non-standard shift types (must be E, D, L, N)


✅ REQUEST #4: DATA LIMITATIONS & PUBLICATION
───────────────────────────────────────────────────────────────────────────────
File: docs/DATA_LIMITATIONS_GUIDE.md (~500 lines)

DATA SOURCES DOCUMENTED:

  Synthetic Benchmark (He et al. 2019)
  │ Realism: ⭐⭐⭐ Controlled but synthetic
  │ Size: 10-30 nurses
  └─ Best for: Paper validation, reproducibility
  
  Hospital Occupancy Proxy (CMS public data)
  │ Realism: ⭐⭐⭐⭐ Real patterns, inferred staffing
  │ Size: 20-25 nurses, 14-21 days
  └─ Best for: Realistic case studies
  
  CMS PBJ Real Data (Public nursing home data)
  │ Realism: ⭐⭐⭐⭐⭐ Actual staffing hours
  │ Size: 30+ nurses, 30 days
  └─ Best for: Long-horizon planning, real deployment

RECOMMENDED DATA SELECTIONS:

  For Paper Main Results:
  → Use: Synthetic Benchmark + Occupancy Proxy
  → Why: Controlled + realistic, shows generalization
  
  For Appendix Case Study:
  → Use: Real CMS PBJ Data
  → Why: Demonstrates real-world applicability
  
  For Sensitivity Analysis:
  → Use: One consistent dataset (test_medium)
  → Why: Isolates parameter effects from data variation
  
  For Computational Benchmarking:
  → Use: Multiple sizes (small → medium → large)
  → Why: Clear scalability demonstration

LIMITATION STATEMENTS (Copy-paste ready!):

  For Synthetic Data:
  ────────────────────────────────────────────────────────
  "Our benchmark case uses synthetically generated demand
  scenarios derived from He et al. (2019). While these
  provide reproducible test cases, they may not capture
  the full complexity of real hospital demand including
  seasonal patterns and emergency surges. We mitigate
  this through validation on real occupancy data (Appendix B)."
  ────────────────────────────────────────────────────────
  
  For Proxy Data:
  ────────────────────────────────────────────────────────
  "Occupancy-based demand is inferred rather than measured
  directly. While it reflects realistic patterns, clinical
  validation would require hospital-specific data and
  clinical team input."
  ────────────────────────────────────────────────────────

DO / DON'T GUIDE:

  ✅ DO SAY:
     "We tested on synthetic benchmark from He et al."
     "Case study uses real hospital occupancy patterns"
     "Model handles realistic demand complexity"
     "Validation on multiple data sources"
  
  ❌ DON'T SAY:
     "We solved a real hospital problem"
     "Results directly improve patient outcomes"
     "Ready for clinical deployment"
     "This is generalizable to all hospitals"
